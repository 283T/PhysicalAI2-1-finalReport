# 開発計画

## 1. 開発環境と挿入動作

- [x] 指定された講義教材の環境を確認する（DebianベースのPushT用Docker、ROS 2・Gazebo設定なし）。
- [x] 課題用のUbuntu 24.04＋ROS 2 Jazzy＋Gazebo HarmonicのDocker設定を用意する。
- [x] 課題用Docker環境でGazeboサーバーを起動し、ROS 2へのシミュレーション時刻の受信を確認する。
- [x] 直交型ロボット、供給トレイ、簡略基板、2ピンコネクタを配置する。
- [x] AIを接続する前に、指定座標で部品1個のピック・挿入を動かす。

完了条件：部品を持ち上げ、基板の穴まで移動し、ピンが穴に入った状態で解放できる。単なる基板表面への配置と区別して確認する。

## 2. 図面と作業指示の形式

- [x] 基板組立図A・Bを作る。原点・mm単位・座標・向きを記載する。
- [x] AI出力の形式を決める。図面ID、部品番号、部品種類、X/Y座標、向きを含める。
- [x] 座標変換と、部品・座標・穴配置の検証を実装する。

完了条件：同じ制御プログラムに異なる作業指示を渡すことで、異なる位置へ挿入できる。現在は向き0度のみ対応。

## 3. AIによる図面読解

- [x] 画像対応モデルを選定し、図面画像から作業指示を抽出する。
- [x] 不足・不正な出力を検出し、実行前に停止できるようにする。
- [x] 図面ごとに手書きした正解データと比較して読解精度を評価する。

完了条件：図面A・Bの画像から抽出した情報で動作が変わる。図面ごとの座標を制御コードへハードコードしない。

## 4. デモと提出

- [ ] 図面、AIの読解結果、ロボットの動作を同時に確認できる表示を作る。
- [ ] 図面AからBへの切り替えを撮影する。
- [x] 読解の正しさと挿入の成功を別々に記録する。
- [x] 実行手順、依存関係、モデル設定、簡略化した物理動作をREADMEへ追記する。
- [ ] PDFレポートと1〜3分の動画を作成する。
