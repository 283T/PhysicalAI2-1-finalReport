# 上面持ち替えから固定P3の挿入へ

実装と事前検査の記録。上面持ち替え・基板接続の物理成功はまだ確認していない。全3接続・最終12試行の成功証拠でもない。現在の物理試験は [Goal記録](goal-status.md) を参照。

`dual_pickup.py` の段階オプションを追加した。

- `--place-in-nest --after-nest-parking`：実際の治具着座が成功した場合だけ、左の支持を開放し、両腕を順に退避する。
- 上記に `--top-regrasp --nest-calibration configs/nest_camera_hd.json`：新規RGB-Dから治具上のP3を認識し、左腕で上面把持・100 mm上昇・4秒保持する。
- さらに `--insert-after-regrasp`：保持後の新規RGB-Dとロボット工具の姿勢から関係を測り直し、監査付きローカルAI図面の指定ソケットへ搬送・挿入する。物理開指と80 mmの上方退避後、2秒以上・10標本以上の安定を検査する。

後段を要求するには前段のオプションも明示する。基板挿入を要求すると、開始前にP3のハウジングと両ピンの有効な接触センサーを検査する。治具カメラはtopic・解像度だけでなく、SDF上の位置・姿勢・視野角と校正値の一致も開始前に検査する。

持ち替え計画は別プロセスで実行し、計算中も治具の独立姿勢監視を続ける。経路は両腕の指の全ストローク、腕同士5 mm・設備1 mmの余裕を囲んで検査する。閉指前には新規画像で再確認し、補正は最大2回・合計5 mm／0.1 rad以内、精密整合0.5 mm／0.005 radと既存の閉指基準を維持する。補正後の実測姿勢でも全閉指ストロークを再検査する。

閉指後は新しい `P3_top_primary` という名前で把持監視を登録する。新規観測を評価してから治具監視を終了し、実際の閉指後の関節から持ち上げを再計算する。既存の `primary`・`support` の参照や記録は上書きしない。上昇70 mm超・滑り5 mm未満・回転0.05 rad未満などの保持基準は変えていない。

挿入の子計画には、新規画像由来の工具との関係とロボット状態だけを渡す。物体真値は独立評価専用。実行前にrequest・world・URDF・基板・AI図面計画のSHAを照合し、開始時の基板・図面計画が変更されていたら拒否する。

## 接触の監視

`connector_contacts.py` は既存ケースを別ディレクトリへコピーし、P1〜P3のハウジングとピンへ計9個の接触センサーを追加する。物理形状・質量・関節は変えない。腕同士と腕・設備の接触は引き続き失敗とする。供給台上の未把持コネクタの接触は診断に残し、腕の衝突と混同しない。

`carried_contact_guard.py` は上昇・保持に実際に成功したコネクタへ登録する。自由搬送中は設備との接触を拒否し、挿入開始時刻以降に限って、図面で選ばれたソケットとの接触を許可する。遅延して届いた接触にもセンサーの時刻を使い、過去の接触へ遡って許可を与えない。他のソケット・供給台への接触は失敗を保持する。開放前に指定ソケットとの実際の接触記録も要求する。センサー間の重複メッセージ数を、接触回数や力と扱わない。

ネイティブ受信コールバックはイベントをキューへ入れるだけとし、コントローラのtickで記録・判定する。これにより接触判定やログ書込みの例外が制御側へ伝わり、終了後の閉じたストリームへ非同期に書かない。専用ログは `carried_contacts.jsonl.gz`。

挿入後は `P3_connected` の監視を登録し、開放・退避後も維持する。既接続端子の監視は、次の端子を動かす実装でも終了しない。現時点のCLIはP3だけの開発用で、`success` は指定した部分工程の成否、`final_acceptance_eligible` はfalseのまま。全端子接続や最終マトリクスの合格へ読み替えない。

## 次の物理試験用シーン

段付き左指を恒久的に含む新規ケースへ、1920×1440の治具カメラと接触計測を追加して `outputs/stepped_nest_contacts_hd_20261016/case` を準備した。左の支持深さ19 mmは、幅50 mmの接触面内へワイヤーが収まることを実モデルで検査した上で指定する。実行中の旧ケースへ指・カメラ・センサーを追加する操作は行っていない。治具カメラの実画像の可視性・認識精度、段付き指での協調把持、接触信号、持ち替え・挿入の物理動作はこれから検証する。

名目着座と両腕退避を仮定した新しい子計画は、持ち替え・挿入とも事前検査を通過し、[要求と計画・検証結果](evaluation/stepped_regrasp_20261016/worker_preflight/validation.json)を保存した。要求JSONのfreshラベルは実行形式を検査するための仮定であり、新規画像の証拠ではない。シーンは追加カメラと9個のセンサーを取り除くと元のXMLと一致し、既存の基板・図面・配置・校正等も同一と確認した。これは実画像や実測着座の代用にせず、物理試験では毎回取得・再計画する。
