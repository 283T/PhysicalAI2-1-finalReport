# 部品1個のピック・挿入デモ

## 実行

リポジトリのルートで実行する。

```bash
docker compose run --rm dev python3 scripts/run_insertion.py
```

スクリプトはGazeboサーバーとROSブリッジを起動し、位置指令・関節状態・部品姿勢・把持状態をROS 2でやり取りする。動作後、確認用プロセスを終了する。結果は`outputs/insertion_result.json`、Gazeboとブリッジのログは`outputs/simulation.log`に保存する。失敗時は終了コードが非ゼロになり、以前の成功結果を残さず失敗理由を書き込む。

現在は手書きの`examples/task_a.json`を入力する。部品1種類・挿入箇所1か所・向き0度に対応し、範囲外の指示は実行前に拒否する。AIによる図面読解は未実装。

## 動作

1. 供給トレイ上の部品位置を取得する。
2. グリッパを部品の上に合わせ、固定ジョイントで把持する。
3. 持ち上げ、基板の穴の上へ移動する。
4. Z軸を下げ、2本のピンを穴へ挿入する。
5. 把持を解放し、ロボットを上へ退避させる。
6. 部品が穴に収まっていることを姿勢・位置から確認する。

## モデルと座標

工場の直交型ロボットを簡略化した、X・Y・Zの3つの直動関節を使う。各軸はGazeboのJointPositionControllerでPID制御する。関節状態を確認してから次の動作へ進む。

| 項目 | 値 |
|---|---|
| 基板原点（ワールド座標） | (0.19, 0.10, 0.12) m、Zは上面 |
| 作業指示の挿入位置 | 基板原点からX=60、Y=50 mm |
| 部品中心の目標 | (0.25, 0.15, 0.13) m |
| 基板の厚み | 20 mm |
| 穴の中心間隔 | 20 mm |
| 穴 | 8 mm角の隙間2個 |
| ピン | 直径4 mm、長さ40 mm、2本 |

基板は複数の直方体で構成する。穴の領域には視覚形状・衝突形状を作らないため、ピンが実際の隙間を通る。部品本体の下面が基板上面に乗る構成で、挿入後に部品位置を直接書き換える処理はない。

挿入深さは「基板上面からピン先端までの距離」とする。成功時は約40 mmで、厚み20 mmの基板を通過して下側へ約20 mm突き出す。

## 成功判定

- 持ち上げ時に部品が供給位置より50 mm以上上昇すること。
- 解放・退避後にX・Y・Zの位置誤差が各1 mm未満であること。
- 姿勢がほぼ初期の垂直姿勢であること（クォータニオンのX・Y・Z成分）。
- ピン先端の挿入深さが30 mmを超えること。
- 把持状態が解放済みであること。

接触力や電気的接続は検査していない。上記はシミュレータの真値による幾何的な成功判定。

## 簡略化と未実装部分

- 部品把持はDetachableJointによる理想的な固定。指の摩擦把持と開閉は再現しておらず、グリッパの指は視覚形状のみ。
- 部品と穴を拡大し、穴のクリアランスを大きくしている。
- 基板・供給トレイは固定。位置情報はシミュレータの真値。
- 回転軸、複数部品、図面読解、カメラによる認識、力制御は未実装。
- GUI表示と録画は未整備。現在のスクリプトはサーバーのみを起動する。

## モデルの変更

worldの生成元は`scripts/build_world.py`。モデルを変更する場合は生成元を編集し、次でSDFを再生成する。

```bash
python3 scripts/build_world.py
```

生成した`sim/worlds/insertion.sdf`もコードと一緒に管理する。`--world`で別のworldを指定できるが、通常のデモは既定のworldを使う。
