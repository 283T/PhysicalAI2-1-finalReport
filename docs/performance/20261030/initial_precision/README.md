# 初回計画を検査カメラで精密化する診断と修正

0.2 ms/I=0の初期world、全ハーネス・全カメラ・元メッシュを使い、腕を動かさず概要RGB-D→検査RGB-Dを新規取得した。
両方とも安定3枚を要求し、検査画像は物理6.0秒で通過した。
終了後のnative照合は物理6.0736秒で、時刻差0.0736秒。検査画像の位置誤差約0.1692 mm／角度0.004693 rad。
概要画像は物理3.0秒のため、同時刻の2カメラ精度比較ではない。両画像の差は約1.696 mm／0.03338 rad。
物体真値は結果照合専用で、目標生成や認識の採否に使っていない。把持・保持の成功を示す実験ではない。
全制御SHA不変と所有プロセス終了を確認し、24原本をr01/へSHA付きで可逆保存した。

最初の起動は診断ファイル名inspect.pyがPython標準ライブラリと衝突してimportで失敗した。シミュレータは起動していない。失敗ログを保持し、check_initial_precision.pyへ変更して実行した。

## 修正候補

scripts/dual_pickup.pyと録画CLIに--refine-initial-with-inspectionを追加した。既定では無効。
概要画像から作ったコネクタ対工具の把持関係を保ったまま、腕を動かす前に新しい検査RGB-Dで物体姿勢を精密化し、最初の経路を計画する。
検査用認識の失敗・端子ID不一致で停止し、粗い目標へ戻して動かすことはしない。真値は使わない。
初期計画前の画像追加であり、動作後の補正予算をリセットしない。既存の閉指前3回照合・最大2回補正・累積5 mm／0.10 rad、優先精度0.5 mm／0.005 rad、把持・接触基準を維持する。
初期検査の時間も実時間録画へ含める。正確さを先に確かめる修正で、速度改善は未確認。

全278テスト通過。追加4件は工具の相対姿勢が非自明でも精密画像目標が最初の経路へ渡ること、既定動作維持、認識失敗・ID不一致で計画や動作を開始しないことを確認する。
次はこの候補を固定して事前登録した新規開発試行を行い、画像補正・全把持・保持・接触・実時間を独立検査する。正式Bや新正式3試行へ後から加えない。
