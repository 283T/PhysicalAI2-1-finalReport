# 精密収束を要求する0.5 ms/I=20開発試行

候補c947ca7。0.5 ms・右第6関節I=20、全カメラ・柔軟ハーネス・元メッシュ、800×600 GUIを維持。
初期静定2.5物理秒後、概要画像の把持関係を新規検査画像で精密化する。
右接近・画像補正のmove終了条件を位置0.5 mm／角度0.005 radへ厳しくし、元の関節0.01 rad・FK1 mm・5観測・時間予算を維持する。
到達しなければ失敗させ、閉指前の画像照合、最大2回補正、累積5 mm／0.10 rad、保持・接触基準を緩めない。
registry.jsonに新規開発試行1回を登録。正式Bや次の正式評価へ後から加えない。
原本outputs/performance_pickup_dt0005_i20_precision_20261030_r01。成功・速さは別々に判断する。

## r01：精密収束の時間切れ（失敗）

初回検査画像と右hoverを通過したが、右approachは物理25.011秒で予算25.0094秒に達した。
終端位置0.521922 mmで0.5 mmを満たさず、角度0.003931 radは0.005 rad内。わずかな超過でも成功に読み替えない。
閉指・保持前、独立監査も失敗。所有プロセス終了、全ソース不変。実録250.421秒、動画249.0秒、全1245パケットの最大PTS間隔0.2秒。
全40原本と後処理方法をr01_failure/へ可逆保存。

終端のFKヤコビアンによる位置誤差の一次分解では右第2関節が約0.4432 mmと最大。合計は実測誤差ベクトルと約0.21 µm以内で一致した。
これは局所的な感度分析で、トルク計測や唯一の原因の証明ではない。
次は右第2関節の積分ゲインだけ100→200に変更する候補を比較する。右手首I=20、P/D、出力・積分上限、物理刻み、認識、精密終了・閉指・保持・接触の基準と時間予算を維持する。
別worldのXMLを比較し、この1要素以外の一致を検査した。新しい試行として事前登録し、正式評価へ混ぜない。

## 第2関節I=200のr02：閉指前照合通過、持ち上げ前に失敗

制御c947ca7、登録8b1534b。右接近の精密終了と新規画像照合を通過し、画像位置0.407965 mm／角度0.004221 rad、追加画像補正なしで閉指へ進んだ。

実録273.060秒、原動画271.6秒、全1358パケットの最大PTS間隔0.2秒。全ソース不変・所有プロセス終了を確認し、49原本と方法をr02_failure/へ保存した。
