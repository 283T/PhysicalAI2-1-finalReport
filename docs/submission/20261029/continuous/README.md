# 双腕の連続動作を見せる改善版（2026-10-29）

ユーザーの「アームが動く様子をカットせず制限時間内で早回し」に対応した確認用動画。

- 動画：`双腕ハーネス_連続動作_16倍速_283t_123.mp4`
- 長さ：168.033秒（説明10秒＋連続動作約150.033秒＋結果8秒）。
- 速度：実時間記録に対して16倍速。シミュレーションの物理時間に対する16倍速という意味ではない。
- 動作：右の接近開始前から双腕保持終了まで、元録画PTS 921.0〜3321.6秒の**1本の連続区間**を使用。途中の動作・待機区間をカットしていない。
- 元録画は5fps。30fpsの早回し出力に合わせてフレームを間引く。物理動作の生成・補間・順序変更はしていない。
- 終盤の視点・拡大率の変化も元録画に含まれる。映像の切り替え編集ではない。

元録画の22.6→921.0秒には898.4秒の記録欠落がある。今回の開始点は欠落直後で、字幕はprimary_observation、両腕は初期姿勢。
その後のprimary_hover（右腕の接近開始）より前から連続表示している。欠落した以前の内容を復元できたとは主張しない。
選択した動作区間内に1秒超のパケット時刻不連続がないことを検査した。

全編デコード・60〜180秒の長さを確認。実出力の説明カード、接近、把持・持上げ・左支持、最終保持など12時点を目視した。
SHAと確認範囲は`validation.json`、生成コードは`build_video.py`。生成にはローカル原録画（SHAを保存）・Pillow・FFmpeg・MacのArial Unicodeフォントが必要。

## 提出版との区別

課題資料の「2倍速再生可」と、既存提出仕様の最大2倍速を超えるため、**提出済み動画を差し替えていない**。
この版は動作全体のレビュー用。YouTubeのアップロード・変更、omnicampusの再提出、制御ソース・物理基準の変更はしていない。
提出条件内で無カットを実現するには、動作時間そのものの短縮・物理時間に同期した新規録画、または講座側への速度条件の確認が別途必要。
正式Bは2成功／3試行。挿入・全端子接続は未達のまま。
