# 把持中心を保つ保持指令の比較実装

**既定では無効、接続成功は未検証。** `dual_pickup.py --centred-grips` で試験へ適用できる。37583で右単独・双腕の100 mm上昇と4秒保持、腕の搬送0〜3は収束したが、未把持P1／P2と治具・右指の接触により工程全体は失敗した。[途中証拠と終了結果](evaluation/centred_hold_20261016/README.md)を保存。従来58060にも再監査でP2と右指の接触が見つかった。評価基準、指の力上限、物理形状・摩擦・刻みは変更しない。

下降中に、右指が閉指時の約2.096／1.926 mmから約0／4 mmへ変わり、コネクタの工具X方向の移動約2.067 mmと対応した。[途中診断](evaluation/grip_centering_20261016/README.md)を保存した。保持基準内でも着座の精度へ影響し得るため、閉じた物体に両指をゼロ位置へ押し続ける指令を比較対象とする。位置だけから実際の力や積分器状態は推定しない。

新方式は、閉指判定後のロボットの指位置だけを参照する。両指の測定値を `q_close` とし、同じ量だけ内側の位置を指令する。

`q_target_i(t) = q_close_i − ε × exp(−Ki / Kp × elapsed_simulation_time)`

両側へ同じオフセットを与えるため、指令の差、すなわち指令上の把持中心は維持される。PIモデルで指位置が固定・飽和なしと仮定すると、減衰するP成分と積分するI成分の和が一定になる。これは微分成分、飽和、摩擦、物体の動きを省いた理想モデルであり、物理的な保持や実測力の証明ではない。[Gazebo 8.15.0のコントローラ](https://github.com/gazebosim/gz-sim/blob/gz-sim8_8.15.0/src/systems/joint_position_controller/JointPositionController.cc) は指令位置と現在位置の差をPIDへ渡し、力を出力する。新方式ではそのゲインをworldから読み、物理を迂回するモードは拒否する。

初期εの上限は右コネクタ1.5 mm、左ワイヤー0.6 mm、左の上面把持0.8 mm。実測値から機械端へ0.2 mmの余裕がない場合は開始せず、余裕が小さい場合の実際のεも記録する。両指のPIDが一致しないモデルは、この方式では未対応として拒否する。新しい参照は変更不能な値として保持し、同じ把持episodeへ二重適用したり、失敗した把持を再参照して成功へ変えたりしない。

元の物体把持参照はそのまま残し、1秒の指令安定待機中も監視を続ける。持ち上げ経路はその後の実測ロボット関節から計算し直す。物体真値は目標生成に使わない。開放時は通常の開指指令へ切り替える。

閉指参照と同じ時刻の観測は新規把持標本へ数えず、治具監視を終える前に新規の把持標本を待つ。待機上限は実時間2秒で、観測が得られない場合は終了せず失敗とする。

初回実装時の250件のテストで、指令中心、範囲、理想PI出力、参照の保持、重複適用・失敗参照の拒否、新規観測への移行を確認した。その後の37583では保持を物理検証したが、搬送は未予定接触で失敗した。今後も成功・失敗の両方を保存する。着座・接続の成功に数えるのは実物理と独立評価が通過した場合だけで、理想モデルを代用しない。
