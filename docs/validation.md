# 図面読解・挿入の検証記録

確認日：2026-10-10。Apple Silicon Mac上のDocker、ROS 2 Jazzy、Gazebo Sim 8.15.0を使用。

## 正常な挿入

`docker compose run --rm dev python3 scripts/run_insertion.py`で実行。

- 部品の持ち上げを確認。
- 解放・退避後の部品中心：(0.25, 0.15, 0.129999736) m。
- 目標：(0.25, 0.15, 0.13) m。
- ピン先端の挿入深さ：約40.0003 mm。
- 把持状態：detached。
- 成功判定：true。

## 穴を外す場合

生成したworldの基板をX方向へ15 mm移動し、作業指示は変更せず実行。供給トレイとロボットは元の位置のまま。

- ピックと基板上への搬送は成功。
- ピンが基板上面に接触し、挿入動作が目標へ到達せずタイムアウト。
- 部品中心のZ：約0.1700 m（正しい着座位置は0.1300 m）。
- スクリプト終了コード：1。
- 結果JSON：success=false。

穴の位置が誤っていても部品が基板を通過して成功扱いになることはなかった。この確認は、力制御や実機の挿入精度を保証するものではない。

再現する場合は、生成したSDFの`fixtures`モデル内で`pcb_`から始まるcollision/visualのposeのXへ0.015 mを加え、別のworldへ保存する。`--world`でそのworldを指定する。生成元と通常のworldは変更しない。

## ローカルAIの図面読解と品種切り替え

Ollama 0.40.2、`qwen3-vl:2b-instruct`（取得時のモデルID：`ea422f1e7365`、配布サイズ約1.9 GB）をMacのMetalで実行。クラウド機能は無効化した。

| 図面 | 抽出された箇所・座標 | 読解時間 | 正解との比較 | 挿入 |
|---|---|---:|---|---|
| A | J1、X=60 / Y=50 mm、0° | 33.8秒 | 6項目すべて一致 | 成功 |
| B | J2、X=100 / Y=90 mm、0° | 26.9秒 | 6項目すべて一致 | 成功 |

6項目は図面ID・ソケット・部品・X・Y・向き。各1回の評価で2/2件一致。モデルへの入力は画像・共通プロンプト・出力形式だけで、正解JSONやソケット座標一覧は渡していない。個数も1個と抽出されたことを実行前に確認した。

抽出JSONをそのまま検証してロボットへ渡し、Aは(0.25, 0.15, 約0.13) m、Bは(0.29, 0.19, 約0.13) mへ挿入・解放・退避した。両方とも挿入深さ約40 mm、success=true。BはGUI表示中に確認した。Aでは`run_from_drawing.py`による画像入力から挿入までの一括実行も成功した。

[読解結果](evaluation/drawing_evaluation.json)、[Aの挿入結果](evaluation/result_J1.json)、[Bの挿入結果](evaluation/result_J2.json)を保存した。各結果にモデル名と画像SHA-256を含める。

これは自作の簡略図面2枚の検証であり、任意の工場図面に対する読解精度を示すものではない。実装位置を切り替えるが、各回は新しい基板・部品で開始する。
