# 図面・認識結果からの双腕到達性確認

図面の全接続指示をカメラで認識した端末に対応させ、MELFA RV-4FRLの関節角を計算する。現在は端末の上方100 mmと、接続先の基板原点高さから160 mm上方への到達性を確認する段階。把持・挿入の成功判定には使用しない。

## 一括実行

```bash
python3 scripts/run_perception_demo.py \
  --design-seed 101 --placement-seed 2 \
  --output outputs/reach_pipeline --evaluate --plan-reach
```

シーン生成、RGB-D取得、MacのローカルQwen3-VLによる今回の図面読解、基板との照合、IK計算を実行する。出力フォルダに`connection_plan.json`と`reach_plan.json`を保存する。モデルへ端末の正解位置や接続表を渡さない。

`--check-reach`を付けると、追加で各腕を**別々の隔離シーン**で動かし、関節状態とGazeboの手先位置で到達を確認する。デスクトップ上のハーネス作業シーンは把持動作を開始しない。

```bash
python3 scripts/run_perception_demo.py \
  --design-seed 101 --placement-seed 2 \
  --output outputs/reach_pipeline --evaluate --check-reach
```

## 運動学と制御

- `build_factory.py`がGazeboに変換する前の左右のURDFを、`outputs/melfa_worlds/left_arm.urdf`と`right_arm.urdf`へ書き出す。運動学の寸法・軸・関節制限を別途手入力しない。
- `arm_kinematics.py`はURDFの固定／回転関節をたどり、シーンの基部位置・姿勢と仮グリッパー先端の80 mmオフセットを加味する。
- 数値IKは幾何ヤコビアン、減衰付き最小二乗、ステップ制限、複数初期値を使う。位置1 mm・姿勢0.015 rad以内を計算上の成功条件とする。関節制限内で同じ姿勢を作る角度を選び、不要な一周回転を抑える。見つからない目標は失敗として返す。
- `plan_reach.py`は全端末の欠落・重複・座標系違い・非有限値を拒否し、端末側と接続先側の両方へ届く腕を列挙する。腕の候補選択は初期関節角からの距離による仮の選択で、作業割り当てや接続順序の確定ではない。
- `check_reach.py`は新しいGazebo/ROS区画で1台ずつ動かす。関節角を滑らかに補間し、目標到達後に位置6 mm・姿勢0.04 rad・関節誤差0.02 rad以内を5回確認する。
- 検証専用のGazeboフランジ姿勢から先端位置を独立に計算し、関節フィードバックからの順運動学と1 mm以内で一致することも要求する。計画器へこの正解姿勢を入力しない。

## 配置と試行で見つかった問題

以前の基部Y=-0.38 mの配置では、配置seed2のP3の上方へ届かなかった。`configs/arm_layout.json`で左右の基部を搬送台の横へ移し、検証した配置では全端末に到達可能な腕を確保した。

最初の動作試行では、手首の角度が十分に整定しなかった。IK解の不要な一周回転を除き、仮のシミュレータ用手首PIDをP=60、D=0.1、I=10へ変更した。大きな姿勢変更後の積分項の整定待ちも最大45秒確保する。これらは実機のチューニング値ではない。公式モデルの質量・慣性は引き続き近似値である。

## 制約と次の作業

これは端点の到達性と隔離シーンの制御確認であり、作業空間の衝突回避、自己衝突、腕同士の干渉、ワイヤーの張力・絡みを含む経路の検証ではない。全ランダム配置の到達保証やIK解が存在しないことの証明にもならない。

カメラから得るのは可視表面と平面yawであり、工具を下向きに仮定している。横倒しの端末のroll/pitchやピンの向きはまだ推定していない。保存した観測の時刻は記録として保持するが、隔離シーンでは過去の目標を再生する。実際の把持前には新しい画像と図面の整合性・時刻を確認する必要がある。

次は完全な端末姿勢・把持点の推定、グリッパーの開閉、もう一方の腕による支持、衝突と接続済み端末の拘束を考慮した経路を実装する。

## 検証結果（2026-10-10）

[保存記録](evaluation/reach_seed2/motion_validation.json)に、8目標の関節指令・位置・姿勢・順運動学の照合結果を記録した。配置seed2、図面D101を対象とした。

- 新しい一括オプションで、今回生成した画像をローカルAIで読み直し、全3接続の照合とIK計画を通過。画像ハッシュも保存した図面と一致。
- 端末側と接続先側の両方に届く候補は、左腕がP1/P2/P3、右腕がP2。現在の仮の割り当ては全端末を左腕に選ぶ。右腕のワイヤー支持への割り当ては未実装。
- 別の観測スナップショットから作った動作計画について、左腕6目標・右腕2目標を、それぞれ隔離シーンで実際に到達させた。全8目標が判定条件を満たした。
- 最大位置誤差5.99 mm、最大姿勢誤差約0.0239 rad。順運動学とGazeboの正解先端位置の差は最大約4.2 µm。これは数値モデルの一致であり、実機精度や材質の正確さを示さない。
- 32件の単体テストと静的検査を通過。解析解との順運動学比較、ヤコビアンの差分検証、IKの到達・到達不可、不正な変換、180度回転、認識と接続表の不整合を確認。

一括処理の計画は`plan.json`・`detections.json`、動作再生の計画は`motion_plan.json`・`motion_detections.json`として、観測時刻の異なる入力を区別して保存している。把持・挿入精度を検証した結果ではない。
