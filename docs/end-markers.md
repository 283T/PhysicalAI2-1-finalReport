# 端面マーカーと把持直前の再観測

既存のハウジング側面マーカーは、指・前後ストッパーで隠れることがありました。`--end-markers` は40×20×20 mmの試作端子の長軸両端に16 mmのArUcoマーカーを加えます。P1はID 0/1、P2は2/3、P3は4/5で、偶数が正のX面、奇数が負のX面です。白地と黒いセルは表示のみで、衝突形状・質量・ケーブルのジョイントを変えません。

`end_markers.py` は、識別したマーカー四隅とRGB-Dの深度平面から端子中心・回転を復元します。画像の拡大は検出を助けるための処理であり、四隅を元の画素座標へ戻してCameraInfoを使います。深度なし、既知寸法との不整合、同じ端子の複数検出を拒否します。端子の真値は復元に与えません。ArUcoの辞書・四隅の識別は[OpenCV公式資料](https://docs.opencv.org/4.13.0/d5/dae/tutorial_aruco_detection.html)を参照しています。実行環境のOpenCV 4.6では、検出器パラメータの初期化に旧APIのファクトリを使用します。

[静止姿勢の記録](evaluation/end_markers/p3_static/validation.json)、[把持直前の姿勢比較](evaluation/end_markers/preclose_guarded/preclose_pose_evaluation.json)に、画像・深度・校正・world・判定・SHA-256を保存しました。後者の画像と真値の時間差は約5 msです。いずれもD101／配置seed2／P3、理想校正の単発試験であり、全端子・ランダム配置・実機の精度を評価していません。静止試験の旧判定ファイルの `xy_error_m` は端面表面と中心の差を含んでおり、復元精度には `center_error_m` を用います。現在の検証器では端面マーカーのXYも復元中心から計算します。

## 閉指前の判定

`--verify-before-close` は把持位置への到達後、指を開いたまま端面を再観測します。画像の端子姿勢と初回認識で選んだ工具との位置関係から、必要な工具姿勢を計算します。実測工具との差が2 mmまたは0.025 rad以上、画像が古い、あるいは要求した端子の観測が欠けていれば閉指しません。`--correct-before-close` を併用すると、ずれが5 mm・0.10 rad以内の場合に限り、開指のまま1回補正します。経路は1 mm・0.01 rad以下の工具姿勢刻みで、直前の関節角を種にIKを解き、関節刻み0.15 radを超える解を拒否します。待機腕を含む既存の箱検査を通して動かし、補正後に新たな安定画像を取得します。再判定の2 mm・0.025 rad基準は変更しません。位置・角度の補正目標に端子のGazebo真値は使いません。

実行したP3の単腕試験では、工具とのずれが約3.29 mm・約2.77°となり、[閉指前に停止](evaluation/end_markers/preclose_guarded/validation.json)しました。開いた状態で再観測する工程まで通過した結果であり、把持・持ち上げ・保持・挿入の成功ではありません。`final_open` は後片付けの開指で、試験の閉指工程 `close` は実行されていません。

保持中の照合と把持直前の再確認には、同じ非同期の観測処理を使います。観測待ちの間も指令とフィードバックを維持します。把持前の認識は従来どおりP1/P2/P3すべてを要求します。診断時の `--plugs` は指定した対象すべてを要求し、今回の単腕検証はP3だけです。双腕の場合は選んだ2端子の観測を要求します。P1・P2の端面認識や双腕での再確認は未評価です。

## 待機腕を含む経路検査

最初のP3単腕試験は、右指と待機中の左上腕が[接触して停止](evaluation/end_markers/single_arm_contact/validation.json)しました。単腕モードでは待機腕が事前の箱検査に含まれていませんでした。修正後は両腕の関節を観測し、待機腕の実測位置を一定経路としてIK候補と実行経路の検査に含めます。待機腕の移動やフィードバック消失も拒否します。IK・箱検査の間に止まっていたROSコールバックは、指令前に処理して新しい観測を確認します。

修正後の[同じシーンでの再試験](evaluation/end_markers/preclose_guarded/validation.json)は接近・下降・端面再観測まで通過し、腕同士の接触記録は0件でした。待機腕を含む包絡箱の検査であり、自己・ケーブル・物体・搬送台との衝突をすべて保証するものではありません。

```bash
python3 scripts/run_perception_demo.py --design-seed 101 --placement-seed 2 \
  --evaluate --pick-connector P3 --regrasp-nest \
  --gripper-p-gain 3000 --capture-gripper --front-fence-side right \
  --end-markers --inspection-calibration configs/end_inspection_camera.json \
  --verify-before-close --verify-held-pose --headless --release-ai-memory \
  --output outputs/end_marker_preclose_p3
```

最終検証は110件の単体テストが通過しています。次は新しい画像姿勢に基づく小さな工具補正を検討し、閉指直前に再度確認します。P1を見られる視点も追加し、双腕の安定把持へ統合します。

## ストッパー幅の比較方法

`--fence-width-mm` は指の前後ストッパーの工具X方向寸法を指定します。既定12 mmを維持し、4–12 mmの有限値のみ許可します。指本体とパッド、前後の21 mmスロット、指の行程・質量・慣性・制御ゲイン、ハーネス物性は変更しません。質量・慣性は試作品の仮定値であり、幅ごとの実物の質量を同定した比較ではありません。

8 mm版は、名目の20 mm幅端子に対して閉指時に4 mmの支持重なりを残します。開指指令18 mmではストッパーの内端が工具中心から22 mmまで退避します（12 mm版は18 mm）。これは端子中心が動かない場合の幾何学的な余裕です。端子が指に追従したり、傾いたりする動的挙動は物理試験で別途判定します。

比較モデルは `--fence-width-mm 8` を付けて生成し、既存の12 mmモデルを上書きしないディレクトリに保存します。

観測器の `acquisition.json` に、処理した画像のシミュレーション時刻・到着後の経過実時間・認識ID・連続安定フレーム数を記録します。3回連続の安定性、画像の鮮度、補正・閉指・保持の基準は従来どおりです。観測期限は既定90秒です。`--inspection-timeout` で5–300秒の有限値を指定でき、観測器・独立検証器・親制御器へ伝播します。観測待ちの間も関節と指の指令・フィードバック・接触監視を継続し、保持中の待機は滑りと回転の判定対象に含めます。保存した最終画像に認識が写っていても、連続安定性の判定に通ったとはみなしません。


8 mm版の最初の[閉指前停止](evaluation/end_markers/fence8_observation_timeout/validation.json)と、[補正後の観測停止](evaluation/end_markers/fence8_corrected_observation_timeout/validation.json)は開放性能を評価していません。後者の診断では、最初の再観測が3フレームで成立するまで60.34秒かかりました。補正後は29.37秒・63.36秒でP3を認識して安定カウント2まで進みましたが、90秒内に3回目が得られず停止しました。途中の未保存画像の挙動やDDSの遅延原因まで同定した結果ではありません。これを受け、比較の追加試験では観測期限のみ180秒とします。


180秒の追加試験も、[補正後の観測中にフィードバック消失](evaluation/end_markers/fence8_feedback_loss/validation.json)で停止しました。観測開始約29秒でP3の画像を1回取得しましたが、約139秒で制御器が新しいフィードバックを得られず、観測子プロセスを停止しました。180秒の期限に達した停止ではありません。両腕の新鮮なフィードバックを要求する条件は緩めていません。観測器は中断時の二重shutdownを避け、例外の種類・理由を診断へ記録するよう更新しています。

停止後の[カメラ単独の取得記録](evaluation/end_markers/fence8_feedback_loss/camera_only/acquisition.json)でも、約29.62秒・88.73秒の2組しか処理されず、90秒で停止しました。制御器からの腕指令はありません。上方カメラは後片付けで5 Hzへ戻っており、物理試験中の0.5 Hzとは異なるので、負荷の厳密な比較には使いません。端面カメラは1 Hzのままです。画像・深度の個別受信数や同期落ち、描画・ブリッジ・DDSのどの段階が主因かは、今回の記録だけでは確定できません。

**8 mmストッパーは実装済みですが、今回の3試験はいずれも閉指前に停止し、保持と開放の効果は未評価です。** 次は画像・深度の個別到着と時刻を計測し、安定した観測経路を復旧した上で、12 mmとの物理比較を再開します。
