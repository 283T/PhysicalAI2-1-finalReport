# 二つの端末を保持する双腕協調

左腕がP1、右腕がP3を保持し、同じハーネスの二端を100 mm持ち上げる中間工程。右腕による支持は別端末の把持で行う。ワイヤー自体の把持、基板への挿入、接続済み端末の拘束制御は、この工程には含まない。

## 実行

```bash
python3 scripts/run_perception_demo.py \
  --design-seed 101 --placement-seed 2 \
  --output outputs/melfa_dual_pick_final --evaluate \
  --pick-connector P1 --support-plug P3
```

図面はローカルQwen3-VLで読み、基板との整合を検証する。動作直前のRGB-D画像から両端末の6D姿勢を計算する。同じ腕を二つの端末へ割り当てず、左右を入れ替えた候補も調べる。把持・上方・接続先のIKが成立する組み合わせから、上方姿勢の関節量が小さいものを選ぶ。接続先のIKは到達可能性の確認のみで、挿入動作は実行しない。

両腕の配置は[arm_layout.json](../configs/arm_layout.json)に記載する。今回の候補は左腕(30, −300) mm、右腕(280, 440) mmで、右腕を作業台の反対側に配置する。P2を右腕で把持する当初の構成では、前腕が左腕の肩・上腕・ベースに近づいた。P3を支持端末に選ぶことで作業領域を分けた。配置や端末を変更した時は事前判定を再実行する。

## 制御と判定

片腕版と同じ`pick_connector.py`を使い、`--support-plug`で双腕へ拡張する。両腕の開指、上方への移動、直線接近、閉指、持ち上げ、保持、解放を共通の状態で実行する。各腕のIK経路に同じシミュレーション時間と進行率を与える。動作前に、腕を作業対象へ向ける初期値などから複数のIK候補を作り、上方・直線下降・100 mmの持ち上げが同じIK分岐で連続する候補を選ぶ。端点だけ解けても、下降時に関節が大きく切り替わる候補は拒否する。選んだ両腕の全経路を包絡箱で確認してから、最初の上方移動を開始する。最初の上方への移動では直立したまま腰軸だけを回す中間点を通り、その後に腕を下げる。直立していない初期姿勢は拒否する。持ち上げ目標は閉指後の実測関節姿勢を起点に、両方のTCPを世界Z方向へ100 mm平行移動する。

経路の端末位置・姿勢は画像由来。Gazeboの真値はFKとの一致、到達誤差、端末の追従・滑り・解放、端末間の間隔を評価するためだけに使う。持ち上げの起点には関節フィードバックから求めたTCPを使う。物体の固定・瞬間移動は使わない。

動作前には次の確認を行う。

- 工具原点間の距離を補間評価し、120 mm未満になる経路を拒否する。
- URDFの接触用STL・箱を囲む姿勢付きの箱を生成し、左右の全リンク間を分離軸法で調べる。各箱を5 mm膨らませ、指は0～20 mmの全可動範囲を囲む。
- 関節変化がサンプル間で0.02 rad以下になるよう、81点以上で経路を調べる。包絡箱が重なる経路は、関節目標を送る前に拒否し、該当リンクを記録する。
- 実行中は左腕の全接触形状をGazeboのContactセンサーで監視し、左右の腕の接触を検出したら停止する。端末との把持接触は左右判定の対象外。

起動時に接触トピックの配信を確認する。[Gazeboの公式実装](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/contact/Contact.cc)は接触がある時だけメッセージを送るため、メッセージ数ゼロと監視なしを区別する。停止時は関節フィードバックを使ってその姿勢を保持し、指を開く。

この判定は離散的な包絡箱の事前確認と実行時の接触停止であり、自己衝突・設備・ケーブルまで含む経路計画ではない。包絡箱には空間も含むため、実形状なら通過できる経路も拒否する場合がある。動作中の視覚追従や力・張力制御も未実装。RGB-Dは動作中に5 Hzから0.5 Hzへ下げ、終了時に元の頻度へ戻す。以前の0.01 Hzでは、復元しても次の画像までの待ち時間が長くなる問題があったため、動作後の画像取得も可能な頻度に変更した。

各端末に[片腕と同じ保持条件](melfa-pickup.md)を要求する。さらに閉指完了時と保持中の端末間の相対位置ベクトルの変化が5 mm未満、保持中の工具間距離が120 mm以上であることを要求する。両端末が70 mm以上上昇し、4シミュレーション秒保持され、解放後に各30 mm以上落下しなければ成功にしない。

## 検証結果

D101／配置seed2で図面読解から双腕の把持・持ち上げ・保持・解放まで一括実行が成功した。[検証原本](evaluation/melfa_dual_pick_seed2/validation.json)、[図面読解と監査](evaluation/melfa_dual_pick_seed2/connection_plan.audit.json)、[再現条件](evaluation/melfa_dual_pick_seed2/manifest.json)を保存した。

| 実測値 | 左腕・P1 | 右腕・P3 |
| --- | ---: | ---: |
| 端末の最小上昇量 | 97.27 mm | 98.43 mm |
| 閉指完了時から保持中の相対ずれ最大 | 2.71 mm | 1.24 mm |
| 保持中だけの相対変動最大 | 0.64 mm | 0.34 mm |
| 解放後の落下量 | 99.04 mm | 99.83 mm |

4シミュレーション秒、両腕共通の1142観測で保持を判定した。端末間の相対位置ベクトルの変化は最大2.62 mm、工具間距離は最小352.13 mm。接触監視の起動確認を通過し、接触メッセージ75435件中に左右腕の接触はなかった（端末等との把持接触は存在する）。上方・下降・持ち上げの実行時の経路判定もすべて通過した。

[左腕の軌跡](evaluation/melfa_dual_pick_seed2/left_arm/pickup.png)と[右腕の軌跡](evaluation/melfa_dual_pick_seed2/right_arm/pickup.png)、10 HzのCSV、動作直前のRGB-D画像と圧縮した深度を保存した。柔軟ケーブルのリンク中心のZ方向範囲は、開指時約12 mmから保持時約101～103 mmに変化した。[測定値](evaluation/melfa_dual_pick_seed2/cable_span.json)。物体を腕へ固定する処理は使っていない。

60件の単体テストを通過。左右の別腕への割り当て、端末間隔の変化・工具経路の交差の拒否、接触相手の分類、回転した包絡箱、5 mmの余裕、腰軸先行回転の初期条件を含む。以前の下降不連続の画像でも、連続経路の選択が成立することを[オフラインで再確認](evaluation/melfa_dual_pick_seed2/continuous_regression.json)した。

この結果は一つの図面・配置・端末組み合わせの検証。保持時間は4秒で、長時間保持、ほかの配置、直接のワイヤー支持や挿入の成功を示すものではない。

事前確認と接触監視の開発では、以下の問題を検出・修正した。

| 試験 | 検出した問題・結果 |
| --- | --- |
| 420 mm間隔、P1/P2同時移動 | 上方への移動が収束せず停止。 |
| 同配置に接触センサー追加 | 動作前からベース同士の接触を記録。STLの張り出し部分が約37 mm重なっていた。配信先・起動時の古いフィードバック取得も修正。 |
| 480 mm間隔 | 右前腕と左肩の接触で停止。 |
| 前後差180 mm | 同じ部位の接触で停止。 |
| 腰軸を先に回転、前後差200 mm | 左上腕と右手首の接触で停止。 |
| 対向配置P1/P3の端点IK | 接触なしで上方へ到達したが、下降IKの不連続を事前検出して停止。連続経路で分岐を選ぶ処理を追加。 |
| 包絡箱で配置と経路を比較 | P1/P2への複数の接近経路を事前に拒否。対向配置のP1/P3経路は事前判定を通過。 |
