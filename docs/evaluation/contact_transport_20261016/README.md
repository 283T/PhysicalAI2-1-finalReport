# 実行中シーンの接触配信の読取り調査

段付き左指を含む試験 `stepped_full_p3_hd64_20261016` が右P3保持・左ホバーを実行している間に、別の購読プロセスから3秒の待機窓で読み取った。Gazebo、腕指令、センサー設定は変更していない。購読を終了した後も元の試験は継続している。

15,043メッセージを受信した。P3のハウジングと右の指のパッドとの接触、未接続P1・P2と供給台との接触を確認した。全ペアと件数は `native_probe.json` に保存した。両側のセンサーから同じペアが届くことがあり、件数を独立した物理接触回数や力とは扱わない。

この環境の `gz sim --versions` は8.15.0。対応する [Gazebo 8.15.0のContact.cc](https://github.com/gazebosim/gz-sim/blob/gz-sim8_8.15.0/src/systems/contact/Contact.cc) では、非停止のPostUpdateでUpdateSensorsを呼び、接触がある各センサーのメッセージを送る。Loadはcollisionとtopicを使うが、update_rateによる周期制御は実装されていない。したがってSDFの `update_rate=30` を実際の配信周波数と見なさない。

大量配信は低速化の候補だが、この測定だけでは主因や改善幅は分からない。追加の購読自身も負荷を加える。RTFの比較やCPUプロファイルは実施しておらず、実行中の配信・監視・物理刻みは変更しない。将来バッチ化を検討する場合も、接触時刻と失敗になる接触を失わないことを先に検証する。
