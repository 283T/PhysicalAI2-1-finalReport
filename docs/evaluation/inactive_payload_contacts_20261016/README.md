# 未把持コネクタと腕の接触：失敗原因の追加調査

37583の最終下降でP2が右グリッパーの指と治具に同時接触し、P1も治具の支持部とガイドに接触していた。P2のピンと右指の接触は物理164.7821秒から、本体と右指は165.1358秒から保存されている。P3の把持ずれが基準内でも、予定していない別コネクタの接触は成功に含めない。

従来の監視は腕同士・腕と設備、およびP3の把持役割を検査していたが、未把持P1・P2と指の接触を除外できていなかった。今回、固定P3の意図した分岐以外（P1・P2本体／ピン／ワイヤー、共有接続部）が腕へ触れたら即時失敗を保持する監視を追加した。共用持ち替え治具へ非対象端子が入り込む接触も拒否し、通常の供給台接触は作業上の接触として扱う。保存ログの監査でも同じ未予定接触を拒否する。単なる微小な追従誤差として押し進めない。

`audit.json` は過去の固定P3失敗3件を、元の記録を変更せず再監査した結果。旧40893にもP1と右指、58060にもP2と右指の接触があった。共用治具も含めると37583は水平搬送2の物理142.9585秒から未予定接触が発生しており、経路追従の収束を工程全体の合格と扱わない。いずれも元から失敗であり、過去の把持単体の通過を接続成功へ読み替えない。メッセージ数は重複センサーを含み、独立した接触回数や力ではない。追従不良の唯一の原因と断定するものでもない。

再計算：

```sh
python3 docs/evaluation/inactive_payload_contacts_20261016/reproduce.py --output /tmp/inactive-payload-audit.json
```

37583は証拠保存後にSIGINTで外部停止した。元の終了報告はsuccess=falseで、SIGINTがROSを先に終了したため最終開指のpublishも失敗した。`external_stop.json` とそのエラーを保存したまま、今後はPythonの割込み後も開指できるようROSの自動signal shutdownを無効にし、KeyboardInterruptも失敗として記録する。実ROS contextへSIGINTを送り、終了時publishが可能なことをテストした。これはロボットで開指成功を検証したものではない。

次は未把持端子が治具・指へ入り込む搬送経路を修正する。既存計画はケーブル出口を反転した候補を先に採用していた。他の向きの候補を、保存済みセンサー要求によるオフライン事前検査から調べ、実行時は新しい画像から計画し直す。既存の基準、摩擦、力上限、ワイヤーを維持する。
